# Council Debates

- Date: 2026-06-17
- Purpose: force useful disagreement before business-engine decisions.

## Prospect Research Council: research-next-lane

- Decision: Should the engine keep using broad regional searches or switch to a narrower source-route experiment?
- Best case: Broad search is fast and can surface unknown businesses without hand-curated directories.
- Hard pushback: Broad search has repeatedly returned locality pages; repeating it burns time and creates false confidence.
- Split: Local scout wants wider coverage; Evidence clerk demands business-owned proof; Skeptic says failed patterns must change; Safety controller allows only public research.
- Verdict: test-smaller-source-route
- Next test: Run research-only query "Yeppoon" "hair salon" "official website"; capture only if public business-owned social/profile, region fit, and website-gap evidence are all present; otherwise log the failed attempt.
- Gate: Research-only; no contact, login, scraping behind login, forms, DMs, calls, or social interaction.

## Titan CEO Council: approval-bottleneck

- Decision: Should the engine promote evidence-ready candidates automatically to unlock outreach work?
- Best case: Promotion would unlock drafts, delivery planning, and pipeline learning faster.
- Hard pushback: Automatic promotion would collapse Daniel approval into automation and weaken the central safety control.
- Split: Operator wants momentum; Investor wants conversion data; Customer advocate wants relevance; Skeptic says trust is lost if the system outruns consent; Builder recommends preserving the gate.
- Verdict: do-not-automate-promotion
- Next test: Review 5 approval packets and record approve, reject, or hold decisions.
- Gate: Daniel approval required before promotion; promotion is still not outreach approval.

## Outreach Review Council: outreach-readiness

- Decision: Should outreach drafts or sends be prepared before approved prospects exist?
- Best case: Drafting early could make the engine feel ready and shorten turnaround after promotion.
- Hard pushback: Drafting against unapproved businesses risks weak relevance, compliance gaps, and accidental send pressure.
- Split: Copy critic wants practice reps; Compliance guard blocks without basis; Buyer empathy lead warns against generic outreach; Daniel proxy requires exact approval.
- Verdict: defer-until-prospect-approved
- Next test: Resolve missing gates; Daniel must approve exact recipient, channel, and copy before any send.
- Gate: No email, SMS, DM, form, social post, call, scheduling, or follow-up without explicit Daniel approval.

## GitHub Work Council: github-remote-issues

- Decision: Should local GitHub issue drafts be created remotely now?
- Best case: Remote issues would make review and tracking easier in GitHub.
- Hard pushback: Remote issue creation is an external write and should not happen just because local artifacts are ready.
- Split: Issue triager likes the structure; Safety controller blocks remote writes; Automation skeptic says local readiness is enough; Builder keeps the command file locked.
- Verdict: keep-local-only
- Next test: Review 5 local readiness rows; ask for exact approval only if Daniel wants remote issues.
- Gate: No remote GitHub writes without explicit approval.

## Web Design Council: concept-publication

- Decision: Should private website concepts be published or shown externally before prospect/outreach approval?
- Best case: A visible concept can make the offer tangible and speed up buyer understanding.
- Hard pushback: Publishing or sending unsolicited concepts can imply endorsement and create reputational risk.
- Split: Conversion designer wants tangible proof; Brand critic wants restraint; Customer advocate wants permission; Skeptic says this sounds premium to the maker, not necessarily to the buyer.
- Verdict: keep-private
- Next test: Use 5 private concepts only for internal review until promotion and outreach approval exist.
- Gate: Do not publish, send, or imply approval of private concepts.

## Offer Pricing Council: offer-model

- Decision: Should the engine keep the flat monthly offer model for current local niches?
- Best case: $0 upfront lowers friction for small local businesses and keeps offers easy to understand.
- Hard pushback: A low-friction offer can attract low-commitment buyers if trust, scope, and cancellation terms are unclear.
- Split: Value strategist likes clarity; Scope controller demands strict deliverables; Buyer advocate wants no surprise fees; Margin keeper watches support load.
- Verdict: keep-model-with-scope-control
- Next test: Use 12 offer strategy rows and 4 forecast stages without treating forecast as booked revenue.
- Gate: Offer strategy is not invoice, proposal send, or client promise approval.
